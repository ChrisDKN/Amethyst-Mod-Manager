# Wabbajack installation

Open **Wabbajack → Browse Wabbajack modlists…** from the Qt toolbar. The button appears only when the current game has gallery modlists or an existing managed Wabbajack installation. Availability uses cached feeds offline and refreshes in the background; game switches and gallery refreshes update the button. The tab can be detached. Browsing, cached feeds, package inspection, and local README viewing do not require Nexus authentication. The browser and installation setup follow the current game selected in the main toolbar. Cards show covers, descriptions, sizes, and installation/update status; tags, sorting, and footer search narrow the results. Setup selects authored profiles, download directory, and managed installation directory. Dropdowns show up to 15 items before scrolling. All authored profiles are selected initially; adult gallery entries are hidden initially.

**Check requirements** loads the modlist package if needed and prepares the requirements and download plan in one step. Review the results, then select **Install** to begin. Blocking failures keep the button on **Recheck requirements**; changing profiles, paths, adjustments, or operation clears the old plan and requires another check. Existing installations use the same two steps, with Resume, Repair, or Update as the final action. Conflicts show installed/author text differences and explicit Keep Mine or Use Author choices. Shared-file changes affect every profile linked to that installation. INIs, saves, enabled states, plugin order, and runtime output remain per profile.

`inspect_package`, `preflight`, `run_install`, `plan_update`, `repair`, and `update` are exported by `Utils.wabbajack`. `InstallRequest` supplies the game adapter, permanent paths, selected profiles, original game sources, optional Nexus API, accepted runtime adjustments, and conflict resolver. `InstallCallbacks` and `InstallControl` come from `Utils.downloads.install`; collection entrypoints retain their existing names and policies. Workers report progress through callbacks and never create Qt widgets.

Requirements checks report their current stage and record stage timings. Each browser keeps a bounded, in-memory verification cache for package integrity, file hashes and BSA size analysis. Rechecks reuse these results only while device, inode, size, modification time and change time match; failed or interrupted checks are not cached. Game paths, selected profiles, runtime capabilities, download-folder contents and available space are checked again. Installation still verifies sources and outputs independently.

The installer uses the collection download/extraction worker settings, memory budget, bounded handoff queue, premium link prefetch and download speed limit. Manual acquisition shares the extraction pool while automatic downloads continue independently. Verified archives appear as queued before becoming active. Each archive bar combines unpacking, nested archives and output reconstruction into one cumulative progress value; completion follows output verification. Progress updates are limited to ten per second, and active archives retain their progress when gaining a visible row. Once acquisition and extraction finish, the main progress display switches to the current operation, including file comparison, publication, ownership recording, rollback and profile catalog refresh. Publication shows file counts and the current path, including copy progress for large files.

Direct HTTP, Wabbajack CDN, public Google Drive and MEGA files, and supported MediaFire/ModDB download pages use automatic acquisition for both free and premium Nexus accounts. Google Drive confirmation forms are handled within the download session. MEGA public file links use streamed decryption, file authentication and the modlist's size/hash verification; interrupted downloads retain their partial file and expired transfer links are refreshed. MEGA folders, account-only sources and other hosts use browser downloads or Select File. Quotas and browser challenges remain host requirements. Failed automatic downloads enter the same manual queue without occupying automatic download workers. The prompt shows the failure reason, author instructions and file-validation feedback. Required archives cannot be skipped; selecting a different version never substitutes for the author's file. Session cookies and temporary download links are not persisted.

Authored modlist separators are moved above their associated mods when preparing Amethyst profiles. Mod priority, enabled states, filenames and empty sections are preserved. Trailing ungrouped mods receive an Ungrouped separator without changing their priority. Staged package modlists keep their authored content; the converted profile files participate in the usual ownership comparison and conflict review during Repair and Update.

For Bethesda profiles, recognised game-root payloads, including `__Files Requiring Manual Install` and `Root Mods`, become one enabled **Wabbajack Root Files** mod shared by the installation's authored profiles. Its root flag preserves paths such as `Data/NVSE/`, and it sits below the curated mods in priority. Script-extender launch paths resolve to the deployed game, including stock-game copies. Other games retain explicit game-root layouts; unfamiliar manual folders remain available with a preflight requirement explaining that their destination needs author guidance.

Publication omits bundled MO2 application files, compiler artifacts and unneeded duplicate profile/overwrite files after importing their settings. Auxiliary tools, their declared dependencies, stock-game copies and unknown content remain. Existing unchanged leftovers are removed through the normal journal and backup transaction during Repair or Update; edited files receive conflict review, and unowned files are preserved. Root payload relocation participates in ownership comparisons, source reuse and space estimates. Copying a patcher does not execute it: additional author-required tools remain listed, while New Vegas's automatic 4GB patch uses the existing game-handler setting.

New Vegas lists with a recognised bundled BSA patcher, or known Viva New Vegas/Mojave Express requirements, automatically receive **Wabbajack Patched BSAs**. Preflight verifies the supported English vanilla archives, FFmpeg's Vorbis/PCM capabilities, and space for staging, converted audio and publication, deducting verified reusable archives. The backend decompresses with Amethyst's archive services, converts affected OGG effects to PCM WAV, preserves music exclusions, removes the invalid vanilla `menus/s.txt`, moves excess meshes into Misc to stay below the game's 2 GiB limit, and preserves the sound/voice flags. Bundled Vorbis libraries, when provided as a complete set, deploy through the generated mod's root files. The standalone wizard remains available separately.

The generated mod uses canonical BSA filenames and is enabled below the curated mods in every selected profile. Original game files remain source material. Per-archive content verification, source fingerprints and a recipe version govern reuse; Meshes and Misc recover together. Edited generated files use the installation's usual conflict review, backups and publication journal. Existing installations receive this step through **Repair**, **Resume** or **Update**. Unknown lists are not assumed to require decompression just because they contain BSAs; unsupported original-file versions receive a specific preflight failure.

Selected profiles that require external TTW output now expose additional setup controls. Choose the author's extracted `.mpi` package and original Fallout 3 installation, or import a complete existing output mod. TTW, separate YUPTTW updates, Ultimate Edition ESM Fixes Remastered, and Fallout 3 ESM/BSA patchers are recognized by their authored mod slots and required outputs. Setup never substitutes a generic TTW profile, adds recommended mods, or changes the supplied plugin order. External content versions remain an explicit author requirement; existing output has no package-supplied version/hash guarantee.

MPI builds use the existing native MPI dependency in an isolated working directory with read-only game sources and no network access. Preflight checks source masters, declared checksums, destination boundaries, the native tool and bubblewrap, and temporary space. Completed output is verified, hashed, staged and published through the installation's normal ownership comparison and rollback journal. Repair reviews edited generated files; completed tasks survive restart and are reused only after verification. An unfinished individual MPI build restarts. The selected external MPI packages and source archives are retained.

Authored `[custom_overrides]` output mods are created even when empty. Their per-profile associations survive import, and authored executables keep their arguments and working directories. Pandora and PGPatcher receive the selected output directory when launched; other tools show a requirement to configure that destination themselves. Arbitrary MO2 output interception is not implemented. Witcher 3 `user.settings`, `dx12user.settings`, and `input.settings` are imported with profile settings and linked during deployment, backing up the original files. Recovery captures game-written changes and restores the originals, including after an interrupted restore.

Bethesda store-specific manual folders select either Steam/GOG or Epic payloads, with ambiguous stores requiring a setup choice. Mojave Express 1.6.1 includes Radio Remaster directly and has no legacy Radio Fix batch step; older packages containing that folder retain a manual requirement. Nuclear Sunset can fill its authored stock-game directory from the original New Vegas files, require the existing automatic 4GB patch setting, and offer removal of the bundled DXVK files as a separate adjustment. Its [Linux guide](https://nuclearsunset.com/docs/main/linux/) remains authoritative for the selected Proton and external TTW/YUPTTW versions.

Optional resolution settings update supported profile INIs, Witcher 3 settings and SSE Display Tweaks through private staged files, retaining normal repair/update conflict handling. Skyrim 1.5.97 profiles using .NET Script Framework can accept installation of .NET Framework 4.8 through the same installer as Proton tools. It backs up the configured prefix, handles Wine Mono registration, verifies Microsoft CLR execution for both installed architectures, and restores the backup on failure. JContainers DLL substitution and Synthesis SDK/NuGet provisioning remain manual requirements. Remaining author and tool instructions are persisted and displayed after completion.

Each installation lives under `<game profile root>/.wabbajack/<installation>/`. Its versioned SQLite database records package identity, ownership, authored baselines, actual hashes, progress, and publication recovery. Profiles use relative links to its shared mods directory. Download caches are independent. Removing the final profile reference removes completed managed installation data; Cache Manager can clear abandoned jobs and update backups.

Gallery feeds and downloaded `.wabbajack` packages live in `<configured download cache>/wabbajack/gallery/`. Existing `<config>/wabbajack/` content migrates on access, including when opening Manage Caches. Settings → Manage Caches lists **Wabbajack gallery and packages** separately from installation jobs/backups. Clearing this folder removes its cached content; installed profiles retain their own saved package and installation database. New gallery data and packages download again when needed.

Downloads require exact size and xxHash64 identity. Required archives cannot be skipped. Nexus links match the pending game domain, mod ID, and file ID. Premium acquisition, manual browser/file selection, HTTP, and multipart CDN acquisition share scheduling and bandwidth controls. Downloads and completed reconstruction survive interrupted jobs. A game-level lock excludes deployment during installation; publication uses backups and a durable rollback journal.

Publication writes rollback entries in batches of 64 and flushes affected directories before committing ownership. Private, singly linked staged files can be linked into place on the same filesystem; shared sources and unsupported filesystems use independent copies. Every published output is hashed, with unchanged file identities and timestamps allowing that verified hash to be reused when recording ownership. Staging rewrites replace files atomically, so retained work cannot overwrite a published file before update review. Post-extraction phase durations are written to the installation log.

Archive and patch processing streams data and limits concurrent work. ZIP compression unsupported by Python is routed through 7-Zip. TES3, BSA 103/104/105, and BA2 GNRL/DX10 versions 1/2/3/7/8 have explicit reconstruction writers with content readback. BA2 extraction selects legacy/DX10 DDS headers and validates declared mip ranges and chunk sizes. LZ4 texture chunks are limited to 256 MiB; tiled textures and password-protected source archives receive explicit failures. Temporary extraction space is estimated before downloading and checked against actual expansion before extraction.

Deterministic files must match their expected hashes and sizes. Remapped files, rebuilt archives, textures, and archive metadata record the actual verified result. Compiled `profiles/*/modlist.txt` files are a format exception: packages can contain cleaned selections while retaining hashes/sizes of the original uncompiled file. Inspection retains that original metadata, derives the expected output from the embedded profile, and reports the discrepancy in preflight. Only this recognized profile format receives that treatment; ordinary inline-file mismatches remain errors.

Texture setup pins Microsoft's Texconv `may2026` executable, SHA256 `dcfdec10244e02cf5037fba089c55fb7e1326b1c8181742d77d15fa5cb5eef06`. **Install Texture Tool** prepares its own Proton prefix and VC++ runtime. Game-prefix dependencies are separate reviewable choices. Stock-game profiles use their reconstructed game-path override and direct prefix launch, retaining the original game location for source verification.
